💻 Module 1: Foundations & Architecture of Computing

1.1 Data, Information, and Knowledge Hierarchies

Understanding the fundamental distinction between structural properties of conceptual inputs:

  • Data: Raw, unorganized, and unprocessed facts, figures, or symbols lacking explicit context (e.g., a list of numbers: 40, 39, 42).
  • Information: Data that has been processed, cleaned, and structured so that it becomes meaningful and useful within a context (e.g., "The average classroom temperature is 40°C").
  • Knowledge: The internalization, interpretation, and application of information by the human mind to make decisions or solve problems (e.g., "The server room is overheating; we must activate secondary cooling units").

1.2 Characteristics of Computers

Modern digital computing systems are defined by key engineering operational hallmarks:

Characteristic Description / Academic Meaning
Speed Calculations executed in microseconds, nanoseconds, or picoseconds.
Accuracy Performs complex computations without computational drift or errors (GIGO principle).
Diligence Immune to fatigue, lack of concentration, or monotony; performs consistently under sustained load.
Versatility Capable of performing completely diverse tasks sequentially or concurrently.
Storage Capacity The facility to store massive amounts of information in highly compact physical footprints.

1.3 The 4 Cognitive Categories of the Human Mind

To contextualize computer performance, we contrast it against the structural faculties of the human mind:

  1. Data Processing / Sensing: The capacity to ingest environmental sensations and raw visual/auditory inputs.
  2. Memory / Retention: Storage of experiences, facts, and emotional connections over variable timelines.
  3. Reasoning / Logic: The cognitive ability to analyze data points, build abstractions, and evaluate morality or risk.
  4. Creativity / Intuition: Generating entirely novel configurations, thoughts, and art without preceding linear patterns.

1.4 History and Classification of Computers

Computing evolved through distinct hardware eras, leading to core classifications based on operational metrics:

The Evolution Eras:
• First Generation: Vacuum Tubes • Second Generation: Transistors • Third Generation: Integrated Circuits (ICs) • Fourth Generation: Microprocessors (VLSI/ULSI) • Fifth Generation: Artificial Intelligence & Quantum Architectures.
Computer Classifications:
• Supercomputers: Maximum capacity, highly parallel systems designed for complex scientific modeling.
• Mainframes: Bulk data processing platforms used by enterprise systems, banks, and governments.
• Minicomputers: Mid-range multi-user systems (historically popular in departmental processing).
• Microcomputers: Consumer-tier personal computing environments (Desktops, Laptops, Mobile Devices).

1.5 Paradigms & Forms of Computing

  • Parallel Computing: Architecture where multiple processors execute parts of a singular structural problem simultaneously to minimize time overhead.
  • Distributed Computing: A network system of discrete standalone computers that communicate and coordinate their actions solely by passing messages over a network to achieve a cohesive goal.
  • Types of Computing Environments: Covers Personal Computing (Standalone), Client-Server Networks, Peer-to-Peer Networks, and Modern Cloud Computing Matrixes.

📊 Module 2: Information Systems & Data Modelling

2.1 What is an Information System (IS)?

An Information System is a formal, organized collection of hardware, software, data, people, and procedures designed to collect, process, store, and distribute information to support organizational decision-making and control.

2.2 The 5 Core Components of an Information System

  1. Hardware: The physical machinery, electronic components, and peripherals (e.g., servers, drives).
  2. Software: The system programs and application packages that govern hardware operational logic.
  3. Data: The underlying raw resource and records processed by the system into meaningful outputs.
  4. Procedures: The rules, policies, and instructional steps governing system usage and operation.
  5. People: The most critical component; includes end-users, operators, systems analysts, and database administrators.

2.3 Foundations of Databases & Entity-Relationship Modeling

A Database is a structured, persistent collection of logically related data items managed to allow easy access, modifications, and updates.

Entities & Relationships:

  • Two Types of Entities:
    • Strong Entity: Can exist independently within the data model; does not depend on another entity type for its key structure.
      • Norhana
    • Weak Entity: Cannot exist independently; its existence is completely dependent on a parent or identifying strong entity.
  • Attributes: The distinct properties or characteristics that describe an entity (e.g., Student ID, Name, Email).
  • Relationships: The structural associations between entities, classified into three cardinalities:
    • One-to-One (1:1): Each record in Entity A relates to exactly one record in Entity B.
    • One-to-Many (1:M): A single record in Entity A relates to multiple records in Entity B.
    • Many-to-Many (M:N): Multiple records in Entity A relate to multiple records in Entity B (requires a junction/associative table to resolve).

🗄️ Module 3: Database Management & MySQL Commands

3.1 Database Management Systems (DBMS)

A DBMS is software that acts as an interface between the database and its end-users or programs, ensuring data security, integrity, and concurrency control.

3.2 SQL Component Languages

  • DDL (Data Definition Language): Commands that define, alter, or drop the physical structure of database schemas (e.g., CREATE, ALTER, DROP, TRUNCATE).
  • DML (Data Manipulation Language): Commands used to manage and manipulate data stored within schema objects (e.g., INSERT, UPDATE, DELETE).
  • DQL (Data Query Language): Commands used to retrieve data from the database (e.g., SELECT).

3.3 Essential MySQL Code Snippets

A reference sheet for standard relational database scripts:

Operation Goal MySQL Command Syntax
Create Table with Keys 
CREATE TABLE Students (
    StudentID INT PRIMARY KEY,
    FirstName VARCHAR(50) NOT NULL,
    GPA DECIMAL(3,2),
    MajorID INT,
    FOREIGN KEY (MajorID) REFERENCES Majors(MajorID)
);
Insert Records 
INSERT INTO Students (StudentID, FirstName, GPA, MajorID) 
VALUES (101, 'Alice', 3.85, 2);
Query with Conditions 
SELECT FirstName, GPA 
FROM Students 
WHERE GPA >= 3.5 
ORDER BY GPA DESC;
Aggregations & Grouping 
SELECT MajorID, AVG(GPA) AS AverageGPA 
FROM Students 
GROUP BY MajorID 
HAVING COUNT(*) > 5;

💾 Module 4: Hardware, Memory & System Storage

4.1 The Von Neumann Architecture

The standard model for digital computing hardware consists of three primary subsystems: the Central Processing Unit (CPU), the Memory Unit, and the Input/Output (I/O) System.

  • Control Unit (CU): Directs the operations of the processor and manages execution steps via the Fetch-Decode-Execute cycle.
  • Arithmetic Logic Unit (ALU): Performs all mathematical equations (addition, subtraction) and logical comparative operations (AND, OR, NOT).
  • Registers: High-speed internal memory cells situated directly within the CPU layout for immediate data access.

4.2 Hierarchical Memory Matrix

Computer memory systems scale along variations of speed, physical cost, and total retention limits:

Memory Tier Volatility Functional Characteristics
Registers Volatile Smallest capacity, located inside CPU core; works at native processor clock speeds.
Cache Memory (L1/L2/L3) Volatile SRAM-based temporary staging area; intercepts recurrent processor instructions to avoid RAM delays.
Primary System RAM Volatile DRAM-based temporary execution space storing current operational code and running applications.
Secondary Storage Non-Volatile Magnetic (HDD) or Solid-State (SSD) flash matrices that store system files and permanent user documentation.

🌐 Module 5: Data Communications & Networking Infrastructure

5.1 Network Topologies

The geometric layout and physical architecture by which network nodes communicate with one another:

  • Star Topology: Every node connects directly to a central hub, switch, or router. If the central hub fails, the entire network drops.
  • Mesh Topology: Every device incorporates redundant point-to-point connections to every other node. Offers unparalleled fault tolerance but high cabling costs.
  • Bus Topology: All nodes share a singular backbone communication cable. Dropouts occur if the terminal ends lose their electrical termination components.

5.2 Network Classification Scale

Networks are categorized based on their geographic operational limits:

  • LAN (Local Area Network): Confined to small localized geographic scopes like a home office, school floor, or single building. High data transfer rates and low latency.
  • MAN (Metropolitan Area Network): Spans an entire municipality, city layout, or university campus system.
  • WAN (Wide Area Network): Crosses country borders, continents, or the entire globe. The Internet is the largest public WAN in existence.

5.3 The OSI Reference Model vs. TCP/IP Stack

Network communications rely on standardized architectural layers to process bits across media:

  1. Application Layer: Direct software interface (HTTP, FTP, SMTP).
  2. Presentation Layer: Data transformation, formatting, encryption, and compression.
  3. Session Layer: Manages, establishes, and closes logical communication sessions between endpoints.
  4. Transport Layer: End-to-end packet reliability, error correction, and traffic flow controls (TCP, UDP).
  5. Network Layer: Routing and logical path addresses (IP Addresses, Routers).
